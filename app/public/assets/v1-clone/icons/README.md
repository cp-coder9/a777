# Canonical origami icon pipeline

Edit `icons/*.svg` and `icons/registry.json`, never `icons/inline/*.svg` or the generated JS. The original 80 SVGs are the supplied Architex pack, already tracked here. Additional canonical SVGs preserve the folded-paper geometry previously held only in reference-001/003/004.js; those scripts are not edited. Dedicated refreshes improve dashboard, practice briefcase, workflow, building, attachment and engineering silhouettes; compound closed/open paths are separated to avoid disappearing white bodies.

The missing documented generator was recovered from git object df24685, then made worktree-relative and deterministic. Run from any working directory:

```
python tools/v1-clone/build_architex_icons.py
node --test app/tests/Frontend/material3-expressive-icons.test.cjs
```

For isolated publication, pass `--output-root E:/Hermes/home/cache/scratch/icon-preview`; this is a repository-shaped destination (assets under `app/public/assets/v1-clone`, sheet under `docs/material3-expressive`). Inputs remain beside the generator. All conversion and coverage checks finish in a private scratch stage before destination files are replaced. Publication is atomic per file with rollback for caught errors, **not multi-file atomic**; readers may observe mixed versions, and power loss/process termination is outside rollback guarantees. Use one publisher at a time. Stage/destination paths are validated before writes.

Tests build two minimal fixtures in E: scratch, copying only canonical SVG/registry inputs, registry data, generator and scanned JS references/modules. Child processes have bounded timeouts (90 seconds for coverage, 120 seconds for builds). They compare every generated byte across builds and against existing checkout artifacts; freshness failures never regenerate the checkout. Injected coverage/publication failures verify unchanged published bytes and rollback. Every canonical conversion is compared with installed geometry.

The generator emits sorted JS metadata/geometry, normalized inline SVGs, conversion-report.json and docs/material3-expressive/icon-contact-sheet.html. No clock, random data or absolute source paths enter outputs. Its XML allowlist rejects executable elements, event attributes, external references, entities and malformed XML; every icon requires an outline and exactly one teal fold. Geometry has no colour or stroke-width; reference-shell.css owns the unchanged palette and font. Module tones remain container CSS.

Approved registry keys intentionally replace the shell's `const iconShapes` lexical binding (not merely window.iconShapes); unregistered extension keys and the protected `logo` key remain untouched. Existing seven icon-map.js tool-family remaps remain valid and are not rewritten. All 49 production tools have explicit mappings; the assembled clone contains 47 tools and 267 tabs. Loaded script/module utilities, global menus and tool mappings resolve 135 required keys with zero missing. The canonical registry contains 188 entries including subservice icons not directly used in top-level menus.

Open the generated contact sheet in Chrome for 752 real inline SVG samples at 20/24/32/48 pixels. This is an isolated visual fixture, not a claim of authenticated application runtime/backend verification. Catalogue copy/download buttons have per-icon accessible names; decorative SVGs are aria-hidden.
