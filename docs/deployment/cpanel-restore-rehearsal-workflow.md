# Explicit cPanel Git restore rehearsal

This is isolated recovery evidence, **not production deployment**, migration authorization, writer-fence evidence, or promotion. Existing unimplemented promotion/DDL gates remain unchanged.

After independent review and publication of the complete reviewed commit, select `restore-rehearsal` in the cPanel Git workflow on master. Supply the independently verified exact lowercase runtime config SHA256. The runner binds the plan to `github.sha`; it pulls the existing managed repository, requires exact remote HEAD, writes an owner-private plan, installs the one-use private API token, invokes real `VersionControlDeployment/create`, polls its exact task and commit, reads a fresh plan/commit-bound receipt, and verifies token-file absence in finally, including failure paths. Cleanup failure invalidates success.

`.cpanel.yml` calls `--from-plan`. That dispatcher accepts only explicit matching `preflight` or `restore-rehearsal` plans. It never automatically invokes live `--deploy`. Explicit CLI requests cannot rewrite a plan's mode. The account-shell hook requires a clean master checkout, exact committed hook bytes, private 0700 root / 0600 owner plan, actual PDO/config/provider-home source preflight, and the reviewed canonical `tools/CpanelRestoreRehearsal.php` implementation. The component validates reflected dependency locations and exact committed source blobs before issuing restore operations.

The source archive is made from a read-only transactional snapshot. APP_KEY remains in process memory; the archive password is retained only in an owner-private recovery journal outside public roots and FILE_STORAGE_PATH. Provider creation/grants and RestoreService DDL affect only generated `archite4_ar_<16 lowercase hex>_test` targets. Source DDL, Apache config, and cron config are untouched. Permission-only hardening remains separately opt-in. A target is retained even after ambiguous provider failure: no unknown retained artifact is removed, and no creation is automatically replayed.

A durable plan-SHA-bound `rehearsal-intent-*.json` prevents hook replay. A retained rehearsal operator plan cannot be reused or rolled automatically, even after successful proof; independent operator reconciliation is required. Old preflight plans can be rolled only with an exact old commit/plan receipt and byte-preserving roll intent. Recovery directories are accepted only with the known name, 0700 metadata, and authenticated owner/home context; inventory never reads archive-password journals. Provider restore JSON is accepted only for known metadata and the disposable target namespace, and is never exported. Unknown inventory fails closed.

Safe workflow artifacts contain only status, commit/plan hashes, sourceDatabaseDdlTouched=false, targetDatabaseDdlTouched, isolatedRehearsalPassed, liveFilesTouched, unchanged Apache/cron flags, target namespace, counts, archive SHA256 and backupId. No passwords, private recovery paths, SQL, full provider responses or arbitrary errors are returned. Restored target snapshots are compared against the immutable source archive, not a changing live source.

Local proof is synthetic only: `python -m unittest discover -s tools/tests -p 'test_cpanel_git*.py'`, `php tools/tests/CpanelRestoreRehearsal_test.php`, PHP lint, and existing private-token tests. Do not treat these as native host backup/restore proof. No hosting operations, production database access, secret worker, commit or push were performed during plumbing implementation. Parent publication must follow independent review; the first actual on-host backup/restore proof remains a separate explicitly authorized workflow run.
